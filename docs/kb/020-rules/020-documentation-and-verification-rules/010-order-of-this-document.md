# Order of this document

This knowledge base is ordered by importance, so a reader who stops early has
still read what matters most. Its index, `docs/kb/README.md`, comes first. The
groups follow it in this order; each one is a file in `docs/kb/` with a
directory of the same name holding its sections:

1. **Mission** (`010-mission`).
2. **Rules** (`020-rules`): the source of truth, documentation and
   verification rules with this ordering, and commits and branches.
3. **Reference** (`030-reference`): architecture, SonarQube and coverage, and
   other standing guidance.
4. **Ongoing work** (`040-ongoing-work`): the work order.
5. **Future work** (`050-future-work`): recorded directions nobody has
   started.
6. **History** (`060-history`): dated records of finished work, oldest first.
   Older records call earlier ones "above", and this order keeps them right.

**Layout.** Every section is one file named `<NNN>-<slug>.md`: a three-digit
prefix that orders it among its siblings, then its title in lowercase words. A
section with subsections has a directory of the same name beside it, where they
follow the same rules. Number new siblings in steps of ten so one can later go
between two without renaming either. A section file starts with front matter,
then its one `# Title`:

```markdown
---
summary: >-
  What the index says about this section, wrapped over as many indented
  lines as needed.
always_read: true
---

# Title
```

`summary` is required and always a folded block (`>-`), which needs no quoting
whatever the text says. `always_read: true` is optional; it puts the section on
the index's *always read* list and marks its entry. Headings inside a section
(`##` and below) are its own structure and stay out of the index; if a part
deserves an entry, it becomes a section of its own.

**The index is generated.** `docs/kb/housekeeping.py` builds the list in
`README.md` between `<!-- kb-index:start -->` and `<!-- kb-index:end -->` from
the files themselves: groups and sections in prefix order, subsections indented
under their section, each linked by path with its summary, the *always read*
ones flagged and also listed on their own at the top. The text above the
markers is written by hand and kept.

- `uv run python docs/kb/housekeeping.py` rewrites the list. Run it after
  adding, removing, renaming, or moving a section, or changing a title or front
  matter.
- `uv run python docs/kb/housekeeping.py --check` changes nothing and fails
  when the list is stale, or when a file breaks the layout above: a bad name, a
  reused prefix, a directory without its section file, missing or unsupported
  front matter, or a file with no `# Title` or more than one.
  `tests/test_kb.py` runs it on this knowledge base, so a stale list fails the
  test suite.

The script is Python, like the package, so pytest can run it; it needs nothing
beyond the standard library.

To keep it in that order:

- Put a new section in the group it belongs to. A new dated record of finished
  work is a new file at the end of History, with the next prefix.
- When work finishes, move its file (and its directory, if it has one) from
  Ongoing work or Future work to History with `git mv` in the same change that
  marks it done, and update the work order.
- When a dated record produces a standing rule, put the rule in Rules or
  Reference, and have the record point to it rather than repeat it.
- Refer to another section by its title; its path is in the index.
- Rewrite the index in the same change.
