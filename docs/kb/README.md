# Knowledge Base

This knowledge base is the working record for maintaining sphinx-typst-render:
how to work in this repository, standing reference, what is in progress, and
what was done and why. It is the single source of truth for maintainers and
agents; `AGENTS.md` (which `CLAUDE.md` and `CODEX.md` link to) only points
here. `README.md` at the repository root stays the public entry point, and
`RELEASING.md` the release procedure.

**Reading it.** Read this index in full, then every section on the
*always read* list below, then go straight to the sections your task needs.
Each section is one file, small enough to read whole, and every entry links to
it by path. Groups run from most to least important (see "Order of this
document" under Rules), and the three-digit prefixes keep sections in that
order on disk as well.

**Changing it.** Edit the section files, never the list below: it is
generated from each section's `# Title` and the `summary` and `always_read` in
its front matter. After adding, removing, renaming, or moving a section, run
`uv run python docs/kb/housekeeping.py` to rewrite the list. With `--check`
it changes nothing and fails while the list is stale or a file breaks the
layout rules; the test suite runs that check (`tests/test_kb.py`). "Order of
this document" under Rules holds those rules.

**Mission**: why the project exists, and the licence everything else follows.

- [Mission](010-mission/010-mission.md) (*always read*) — What sphinx-typst-render is (a Sphinx and Jupyter Book extension that turns Typst sources into PDFs, previews, fillable forms, download-menu entries, an overview page and an in-browser editor) and whom it serves (NB-TUDelft course books); the editor is maintained here alone, never ported from or kept close to the discontinued EI_Logbooks site; `AGPL-3.0-or-later` since 1.0.0, MIT up to 0.2.5; bundled third-party code keeps its own licence and notice.

**Rules**: how to work in this repository, verify, commit, and keep this knowledge base.

- [Maintainer and Agent Source of Truth](020-rules/010-maintainer-and-agent-source-of-truth.md) (*always read*) — Names this knowledge base the single source of truth for maintainers and agents; `README.md` stays the public entry point (it is also the PyPI page) and `RELEASING.md` the release procedure; the one agent file, `AGENTS.md` (`CLAUDE.md` and `CODEX.md` are symlinks to it), stays pointer-only.
- [Documentation and Verification Rules](020-rules/020-documentation-and-verification-rules.md) (*always read*) — Standing rules: tests ship with behaviour changes; Python is formatted with Ruff and JavaScript with Biome; the gate before a commit (Ruff's check and pytest with coverage, then for editor changes Biome, the build and the browser test with coverage, then SonarQube `OK`); fix touched-file issues; never weaken a check; small commits; record the checks run; keep this knowledge base current while working.
  - [Order of this document](020-rules/020-documentation-and-verification-rules/010-order-of-this-document.md) (*always read*) — Standing rule: the knowledge base is one file per section under `docs/kb/`, in groups (Mission, Rules, Reference, Ongoing work, Future work, History oldest first) ordered by three-digit prefixes; how to place new and finished work; the index generated by `docs/kb/housekeeping.py` from each section's title and front matter, and checked by the test suite.
- [Commits and branches](020-rules/030-commits-and-branches.md) (*always read*) — Standing rules: `main` is the release branch and work branches merge into it (`claude/<topic>` for agents; `v0` keeps the 0.x line); commits and tags are signed and signing is never bypassed; commit or push only when the maintainer asks; subject lines in the style of the recent history.

**Reference**: standing guidance to read when a task touches its area.

- [Current Architecture](030-reference/010-current-architecture.md) — Layer map: `__init__.py` (`setup()`, the `typst_render_*` config values, event hooks), `_compile.py`, `_directive.py`, `_downloads.py`, `_overview.py`, `_editor.py` with its generated `_editor/` bundle built from `editor/`, `static/` and `fonts/`; the tests, the browser test and the two workflows; no console script (the template's broken one went after 1.1.2).
- [SonarQube and coverage](030-reference/020-sonarqube-and-coverage.md) — SonarQube project `sphinx-typst-render` (`sonar-project.properties`): plain `sonar-scanner` with host and token from the scanner's own configuration, never an empty `SONAR_TOKEN`, never either recorded here; Python coverage from `pytest --cov`, the editor's from its browser test through V8 and c8 (`pnpm run coverage`), each snapshot reported alone and added up, since c8 adds them up wrongly, and why its `--exclude-after-remap` is not used; what coverage leaves out; `sonar.projectVersion` advances with releases.
- [Editor code conventions](030-reference/030-editor-code-conventions.md) — Standing guidance from the SonarQube clean-up (`2026-11-22`): independent async work runs together, work that must not overlap goes through `inSequence()` with the reason beside it; `void` only on promises whose function handles its own errors; long functions become named steps, since SonarQube counts nested functions into the outer one; a change to the export is checked against an export made before it (`tools/compare_exports.py`).

**Ongoing work**: what is in progress, in the order to take it up.

- [Work order](040-ongoing-work/010-work-order.md) (*always read*) — The work order (`2026-11-22`): in `editor/biome.json`, add `coverage.mjs` and the download menu's script to Biome's files and drop the HTML `tabindex` exemption (the maintainer's, behind a local hook).

**Future work**: recorded directions nobody has started.

- [Conda packages](050-future-work/010-conda-packages.md) — Conda publishing stays off until `typst` (the Python binding) and `typst-fillable` are on conda-forge; `RELEASING.md`, "Conda is off, and why", has the reasons and the steps to turn it on.
- [A test for the download menu script](050-future-work/020-a-test-for-the-download-menu-script.md) — `static/typst-render.js` runs only in the browser and no test exercises it, so SonarQube's coverage leaves it out; a browser test of a built page would bring it in, reusing the editor test's Playwright and V8 coverage setup.
